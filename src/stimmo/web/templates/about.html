How stimmo turns an address + asking price into an UNDER / FAIR / OVER verdict, and what data backs it.

The pipeline

  1. Geocode the address via OSM Nominatim to get latitude / longitude.
  2. Locate the OMI zone by point-in-polygon against Milano's official zone boundaries.
  3. Look up the €/m² band (Compr_min–Compr_max) for that zone, property type, and condition bucket.
  4. Count nearby amenities within a 500 m radius via OSM Overpass.
  5. Adjust the band with a single coefficients table (floor, lift, fine condition, energy class, outdoor, box, amenity score).
  6. Multiply by surface to get the estimated price range, then classify the asking price as UNDER / FAIR / OVER with a ±5% tolerance.

No machine learning

stimmo has no trained model. The entire tuning surface is a single coefficients file (valuation/adjustments.py). The verdict is deterministic: same inputs, same output.

Asking-vs-rogito premium

OMI publishes transacted prices (rogiti from the notarial act). In Milano, asking prices typically run 5–10% above the eventual sale price. We shift the OMI range upward by a fixed +6% ask-premium before classifying the verdict, so a listing at rogito mid correctly shows as mildly under-priced and a listing at rogito + 6% shows as fair. Both the rogito range and the typical-Milano-ask range are visible on the result page. The constant lives in valuation/verdict.py::ASK_PREMIUM_PCT.
